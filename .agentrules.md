# Kestrel Agent Rules

## Git Workflow & Branching
1. **Base Branch**: Always branch off the staging branch (`dev`) for new features or bug fixes.
2. **Standard Prefixes**: Name branches using prefix-based kebab-case:
   - `feat/<short-description>`
   - `fix/<short-description>`
   - `refactor/<short-description>`
   - `chore/<short-description>`
3. **No Direct Pushes**: Never push directly to protected branches (`main`, `dev`). All changes must be submitted via pull requests.

## Commit & PR Standards
1. **Conventional Format**: Structure all commit messages using Conventional Commits format (`<type>(<scope>): <imperative summary>`).
2. **Subject Line**: Explicitly state what change is made and why. Do NOT include task IDs in the subject.
3. **Task IDs**: Include optional task manager identifier (e.g. Notion, Linear) in the commit footer when applicable (e.g., `For: K-123`).

## Execution Parity
1. **Mise Task Parity**: GitHub Actions workflows and local execution MUST utilize the `mise` task runner. Do not raw-dog commands in workflows.
2. **Toolchain Discipline**: Run `mise run <task>` to execute checks locally. Do not bypass git hooks.
3. **Dependency Tracking**: Never install tools or dependencies ad-hoc without persisting them in `Cargo.toml`, `package.json`, or `mise.toml`.

## Tech Stack & Code Quality
1. **Tech Stack Adherence**: Adhere strictly to the established tech stack, libraries, and frameworks of the project.
2. **Tooling & Integration Discipline**: Use MCP integrations and available skills first before attempting to manually scrape or bypass external services.
